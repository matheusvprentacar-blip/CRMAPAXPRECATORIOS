# 2026-04-22

## Atualizações

### Kanban: retorno específico de análise para triagem
- Contexto: operação solicitou permitir apenas a volta de cartões da etapa de análise jurídica/processual para a triagem no Kanban.
- Mudanças:
  - ajuste na lógica de drag-and-drop para permitir retorno direto para `triagem_interesse` quando a origem for `analise_processual_inicial` (incluindo casos com status `juridico`/`analise_juridica`)
  - manutenção do modal de triagem para os demais fluxos que entram em `triagem_interesse`
  - atualização da documentação do módulo Kanban no vault
- Arquivos/áreas impactadas: `app/(dashboard)/kanban/page.tsx`, `CRM APAX/Módulos/Kanban.md`
- Decisão tomada: liberar apenas esse retorno operacional específico sem abrir exceção geral para todas as colunas.
- Pendências/próximos passos: validar em homologação com usuário jurídico/comercial se o retorno direto cobre 100% do cenário esperado.

### Detalhes do precatório: volta para triagem na barra de status
- Contexto: mesmo com a regra no Kanban, a tela de detalhes ainda não permitia retornar da análise para triagem.
- Mudanças:
  - inclusão do botão `Voltar para triagem` na barra de status de `/precatorios/detalhes`
  - permissão do botão ajustada para `admin`, `juridico`, `operador` e `operador_comercial`
  - ação disponível apenas para os estados de análise (`analise_processual_inicial`, `juridico` e legado `analise_juridica`)
  - atualização direta de `status_kanban` e `localizacao_kanban` para `triagem_interesse` com recarga da ficha
  - atualização da nota temática do módulo Kanban
- Arquivos/áreas impactadas: `app/(dashboard)/precatorios/detalhes/page.tsx`, `CRM APAX/Módulos/Kanban.md`
- Decisão tomada: manter simetria entre Kanban e tela de detalhes para o mesmo retorno operacional específico.
- Pendências/próximos passos: validar se o botão deve registrar auditoria específica de retorno (além da trilha padrão de update).
